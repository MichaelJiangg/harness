# 模型权限裁决器研究方案

> 状态：待研究
> 日期：2026-09-20
> 范围：优化 `auto` 模式，减少常规操作的权限弹窗，同时避免把 `auto` 变成跳过安全判断。
> 依据：Claude Code 官方权限模式文档、DeepSeek 官方模型与定价文档。

## 目标

在不引入第三方依赖和真正沙箱的前提下，用独立的 DeepSeek 模型对“确定性规则无法判断安全”的动作做语义裁决，返回 `allow`、`deny`、`ask` 或 `unclear`。

这不是让主 Agent 自己判断权限，也不是把模型裁决当作唯一防线。模型只处理需要语义判断的中间层，硬禁止、受保护路径和用户显式规则仍然由本地代码优先执行。

## 白名单与模型排列

推荐顺序为：

```text
1. 硬拒绝：deny、关键删除路径、受保护路径
2. 显式询问：用户配置的 ask 规则
3. 保守白名单：确定安全且低风险
4. 模型裁决：白名单未命中、需要理解意图的动作
5. 人工回退：模型要求确认、无法确认或失败关闭
```

白名单优先于模型，原因是成本、延迟和确定性：常见只读操作不应该每次都调用模型。模型优先于普通用户确认，原因是在 `auto` 模式下减少重复人工弹窗。

模型只能覆盖“白名单未命中”的普通裁决，不能覆盖第 1、2 层，也不能覆盖用户已经明确划定的对话边界。

## 分层细节

### 第 1 层：硬拒绝

本地代码先执行，模型返回 `allow` 也不能推翻：

- 工具级或规则级 `deny`。
- `rm -rf /`、`rm -rf ~`、删除工作区父目录等关键路径。
- 写入 `.git`、`.env*`、`.harness`、`.claude` 等受保护路径。
- 用户在当前对话中明确说过“不要 push”“部署前等我确认”等边界。
- 模型自身或分类请求失败时的失败关闭结果。

### 第 2 层：显式询问

命中用户配置的 `ask` 规则时，直接交给本地确认，不调用模型。`auto` 模式不应自动吞掉用户明确要求人工确认的规则。

当前实现里 `auto` 可能先于规则放行，实施模型裁决前需要先修正这个顺序。

### 第 3 层：保守白名单

以下动作不调用模型：

- 工作区内的 `read_file`、`grep`。
- 工作区或已信任目录内的普通 `write_file`、`run_verify`。
- 已明确识别的只读 Bash 命令。
- 不涉及代码执行、网络或数据外发的窄范围 `allow` 规则。

进入 `auto` 模式时，以下宽泛规则不得直接跳过模型：

- `Bash(*)` 一类任意代码执行规则。
- `python*`、`node*` 一类解释器通配规则。
- `npm run` 一类包管理器执行规则。

白名单必须保持保守。如果一条规则存在明显绕过空间，宁可交给模型，也不能扩大静态放行。

### 第 4 层：模型裁决

需要交给模型的动作示例：

- 本地执行代码，但脚本内容或参数无法被静态规则证明安全。
- 安装依赖、修改环境、执行未知工具。
- 网络读取、上传、下载，但尚未达到 `curl | bash` 这类直接硬拒绝等级。
- Git 提交、推送、远端操作和 PR。
- 对非关键路径的删除、覆盖和批量修改。
- `delegate` 启动前的任务描述。
- `delegate`、`swarm` 最终报告回传主 Agent 前。
- Swarm 的角色交接，尤其是 Coder 到 Reviewer 之后产生的修改。

默认裁决模型使用 `deepseek-v4-pro`。主 Agent 当前使用 `deepseek-flash`，因此分类模型与执行模型应保持独立，避免同一个模型既产生高风险动作又批准自己。

`deepseek-flash` 可以作为低风险预筛，但它返回 `unclear`、低置信度或与静态规则冲突时，必须升级到 Pro。第一版可以只实现 Pro 裁决，不实现双模型预筛。

### 第 5 层：人工回退

以下情况转人工：

- 模型返回 `ask` 或 `unclear`。
- 模型返回低置信度 `allow`。
- 模型请求超时、限流、返回格式错误。
- 模型连续 3 次 `deny`，或同一会话累计 20 次 `deny`，暂时暂停模型裁决。

交互模式下恢复逐次确认；非交互模式没有确认入口，继续保持拒绝并让主 Agent 尝试替代方案，不能阻塞等待。

用户人工批准一次后，可以恢复模型裁决。

## 模型请求契约

### 输入

分类请求是独立请求，不进入主 Agent 对话。系统消息包含：

- 固定裁决角色说明。
- 必须返回的 JSON 格式。
- 禁止放行的硬规则。
- 当前工作区、信任目录和会话开始时的 Git 远端。

用户消息包含：

- 最近用户目标或最近完整用户轮次摘要。
- 最近若干非只读工具调用名称和脱敏参数。
- 本次待裁决的工具名称和参数。
- 适用的权限规则摘要。

不包含：

- 文件正文。
- `grep` 或 `read_file` 的返回内容。
- Bash 命令输出。
- 网页或 API 返回内容。
- 日志内容。

对命令参数中的明显密钥、token、cookie 和邮箱类内容先脱敏，再发给分类模型。

### 输出

使用 DeepSeek JSON Output，继续禁用 thinking，限制短输出：

```json
{
  "verdict": "allow",
  "confidence": "high",
  "rule": "safe_local_action",
  "reason": "操作位于工作区内，且与当前测试目标一致"
}
```

字段：

| 字段 | 取值 |
| --- | --- |
| `verdict` | `allow`、`deny`、`ask`、`unclear` |
| `confidence` | `high`、`medium`、`low` |
| `rule` | 固定规则码 |
| `reason` | 最多 120 字，且不包含密钥或工具结果正文 |

建议的第一批规则码：

- `safe_local_action`
- `intent_mismatch`
- `outside_workspace`
- `data_exfiltration`
- `secret_exposure`
- `destructive_action`
- `untrusted_network`
- `privilege_escalation`
- `missing_context`
- `human_review`

未知字段、未知规则码、非法 JSON、缺少必要字段均按 `unclear` 处理。

### 裁决解释

| 模型结果 | Harness 行为 |
| --- | --- |
| `allow` + `high` | 执行 |
| `allow` + `medium` | 执行，但审计中标记需要观察 |
| `allow` + `low` | 按 `ask` 处理 |
| `ask` | 交互确认；非交互拒绝 |
| `deny` | 返回安全错误给主 Agent，不执行 |
| `unclear` | 交互确认；非交互拒绝 |
| 请求失败 | 交互确认；非交互拒绝 |

## 建议配置

```toml
[tool.harness.safety]
enabled = true
model = "deepseek-v4-pro"
timeout = 8
max_context_chars = 4000
max_verdict_tokens = 240
recent_actions = 12
max_consecutive_denies = 3
max_total_denies = 20
```

首版只在 `auto` 模式启用模型裁决，`ask` 模式继续使用当前确定性逻辑。

## 费用与审计

分类请求单独计入 `UsageLedger`，来源标记为 `safety`，记录：

- 模型名称。
- 输入和输出 token。
- 裁决、规则码和置信度。
- 延迟。
- 是否因连续拒绝触发人工回退。

审计仍不得记录密钥、文件正文、工具结果正文或完整分类 Prompt。

## 集成点

- 新增独立模块，例如 `harness/safety.py`。
- `PermissionPolicy` 继续只做确定性判断，不在其中发起网络请求。
- `tools/executor.py` 在确定性决策为“需要模型”时调用 Safety Reviewer。
- 模型裁决在工具副作用和本地确认之前完成。
- `delegate` 和 `swarm` 在启动前、最终报告回传前增加检查点。
- CLI 可增加 `[safety]` 裁决事件，但默认只显示阻止或回退，不打印模型 Prompt。

## 暂不实施

- 不把模型裁决扩展到 `ask` 模式。
- 不引入第三方 SDK 或真正文件系统沙箱。
- 不让模型覆盖 `deny`、受保护路径和关键删除路径。
- 不把文件正文和工具输出放入分类请求。
